The x86 Plugin

See also
mim::plug::x86

The native x86-64 backend. Loading this plugin (mim foo.mim -p x86) appends instruction selection and emission to the compilation pipeline. Instruction selection rewrites core, math, and mem into the axioms below. A literal operand of an instruction is an immediate and has to fit its encoding; mov puts any other constant into a register. Registers are no concern of these types; register allocation introduces them later. The schedule is the mem.M 0 chain: memory instructions sit on it, and scheduling threads all other instructions onto it via sched.

Dependencies

plugin core;
plugin mem;
plugin math;
plugin opt;
plugin refly;

Types

Flags

The flags register.

axm Flags: *;

Addr

A memory operand disp(base, index, scale); the Bool states whether it has an index. It is no value and occupies no register of its own; only memory instructions and lea take one.

axm Addr: Bool → *;

Base

An address disp(base) without an index.

anx let Base = Addr ff;

Index

An address disp(base, index, scale).

anx let Index = Addr tt;

addr

addr (disp, base) addresses disp + base, like AT&T's disp(base). A literal 0I64 as base means there is none. A literal base folds into disp if the sum fits, else it goes into a register.

axm addr: [disp: I32, base: I64] → Base, normalize_addr;

index

index a (i, scale) addresses a + (i << scale), like AT&T's disp(base, index, scale). An address has at most one index.

axm index: Base → [index: I64, scale: I2] → Index;

These lets name the scales.

anx let scale_1 = 0I2;
anx let scale_2 = 1I2;
anx let scale_4 = 2I2;
anx let scale_8 = 3I2;

Spill

A spill slot holding a value of type Idx s. It is no register value; slot assignment gives it a place in the stack frame.

axm Spill: Nat → *;

FSpill

A spill slot holding a floating-point value of type math.F pe.

axm FSpill: «2; Nat» → *;

Operand Sizes

Instructions are polymorphic in the operand size s and state which sizes they support via refly.check in their codomain. A literal s folds the check away; an unsupported one is an error.

lam is (s n: Nat): Bool = core.ncmp.e (s, n);

gpr

i8, i16, i32, or i64.

anx lam gpr (s: Nat): Nat =
let ok = core.bit2.or 0 (core.bit2.or 0 (is (s, i8), is (s, i16)), core.bit2.or 0 (is (s, i32), is (s, i64)));
refly.check (ok, s, "x86: operand size must be i8, i16, i32, or i64");

gpr16

i16, i32, or i64.

anx lam gpr16 (s: Nat): Nat =
let ok = core.bit2.or 0 (is (s, i16), core.bit2.or 0 (is (s, i32), is (s, i64)));
refly.check (ok, s, "x86: operand size must be i16, i32, or i64");

logic

Bool or a gpr size.

anx lam logic (s: Nat): Nat =
let ok = core.bit2.or 0 (is (s, 2), core.bit2.or 0 (core.bit2.or 0 (is (s, i8), is (s, i16)), core.bit2.or 0 (is (s, i32), is (s, i64))));
refly.check (ok, s, "x86: operand size must be Bool, i8, i16, i32, or i64");

fpe

math.f32 or math.f64.

anx lam fpe (pe: «2; Nat»): «2; Nat» =
let (p, e) = pe;
let (p32, e32) = math.f32;
let (p64, e64) = math.f64;
let eq32 = core.bit2.and 0 (core.ncmp.e (p, p32), core.ncmp.e (e, e32));
let eq64 = core.bit2.and 0 (core.ncmp.e (p, p64), core.ncmp.e (e, e64));
refly.check (core.bit2.or 0 (eq32, eq64), pe, "x86: float type must be f32 or f64");

Instruction Forms

The plugin pretends that x86 uses three-address code and copes with x86's two-address code later on. However, some artifacts shine through: for two-address instructions the tied value operand comes first; the tie is only a register-assignment constraint (add (a, b) computes a + b), and x86.emit reverses the value operands for its AT&T output.

rm

op r, addr: rm f (m, a, addr) is f (a, b) with b loaded from addr.

axm rm: {T C: *, i: Bool} → («2; T» → C) → [mem.M 0, T, Addr i] → [mem.M 0, C];

rm1

op r, addr of a unary operation: rm1 f (m, addr) is f b with b loaded from addr.

axm rm1: {T C: *, i: Bool} → (T → C) → [mem.M 0, Addr i] → [mem.M 0, C];

mr

op addr, r: mr f (m, addr, b) stores f (a, b) to addr with a loaded from addr.

axm mr: {s: Nat, C: *, i: Bool} → («2; Idx s» → C) → [mem.M 0, Addr i, Idx s] → mem.M 0;

sched

Places the pure instruction f x on the mem.M 0 chain right after m: let (m, y) = x86.sched x86.add m (a, b). The chain token makes each placement a distinct Def, so copies, spills, and reloads at different points never merge.

axm sched: {D C: *} → (D → C) → mem.M 0 → D → [mem.M 0, C];

Registers

in

in r v is v, which lives in register r; the operand size s selects the subregister. Register allocation wraps every use of a value, so all uses of v share one in r v. It is no instruction: it is neither scheduled nor on the chain.

axm in: [r: I4] → {s: Nat} → Idx s → Idx s;

fin

fin r v is the floating-point value v, which lives in XMM register r.

axm fin: [r: I4] → {pe: «2; Nat»} → math.F pe → math.F pe;

Instructions

lea

lea r, addr materializes an address as a value. The address addr (0, b) is b, and addr (d, 0) the literal d.

axm lea: {i: Bool} → Addr i → I64, normalize_lea;

mov

mov r, imm materializes a constant.

axm mov: {s: Nat} → Idx s → Idx (logic s);

load

mov r, addr.

axm load: [s: Nat] → {i: Bool} → [mem.M 0, Addr i] → [mem.M 0, Idx (gpr s)];

store

mov addr, r.

axm store: {s: Nat, i: Bool} → [mem.M 0, Addr i, Idx s] → mem.M 0;

slot

Reserves n bytes in the stack frame and yields their address via lea.

axm slot: [n: Nat] → mem.M 0 → [mem.M 0, I64];

spill

spill x stores x into a spill slot; it is placed on the chain via sched like any other pure instruction.

axm spill: {s: Nat} → Idx s → Spill s;

reload

reload x loads x from its spill slot.

axm reload: {s: Nat} → Spill s → Idx s;

cmovcc.l (f, x, y) yields y if l holds on f, else x, like (x, y)#cond.

axm cmovcc.(o, no, b, ae, e, ne, be, a, s, ns, p, np, l, ge, le, g): {s: Nat} → [Flags, Idx s, Idx s] → Idx (gpr16 s), normalize_cmovcc;

Floating-Point Instructions

Floating-point values live in the XMM registers; the type math.F pe is one value, so its format depends on pe. An operand is never an immediate: a literal is materialized by fmov first.

fmov

mov r, imm materializes a floating-point constant from the constant pool.

axm fmov: {pe: «2; Nat»} → math.F pe → math.F (fpe pe);

fload

movss/movsd r, addr.

axm fload: [pe: «2; Nat»] → {i: Bool} → [mem.M 0, Addr i] → [mem.M 0, math.F (fpe pe)];

fstore

movss/movsd addr, r.

axm fstore: {pe: «2; Nat», i: Bool} → [mem.M 0, Addr i, math.F pe] → mem.M 0;

fspill

fspill x stores the floating-point value x into a spill slot; it is placed on the chain via sched like any other pure instruction.

axm fspill: {pe: «2; Nat»} → math.F pe → FSpill pe;

freload

freload x loads x from its floating-point spill slot.

axm freload: {pe: «2; Nat»} → FSpill pe → math.F (fpe pe);

Floating-Point Arithmetic

Two-address arithmetic op r, r.

axm (fadd, fsub, fmul, fdiv): {pe: «2; Nat»} → «2; math.F pe» → math.F (fpe pe);

Floating-Point Unary

sqrtss/sqrtsd and andps/andpd with a mask clearing the sign bit.

axm (fsqrt, fabs): {pe: «2; Nat»} → math.F pe → math.F (fpe pe);

fsel

fsel (c, x, y) yields y if c holds, else x, like (x, y)#c.

axm fsel: {pe: «2; Nat»} → [Bool, math.F pe, math.F pe] → math.F (fpe pe);

Floating-Point Conversions

Both formats and sizes are explicit, since a folded load (x86.rm1) leaves no operand to infer them from. The instances of x86_isel name the sizes; only i32 and i64 are supported.

axm i2f: [s: Nat] → [pe: «2; Nat»] → Idx s → math.F (fpe pe);
axm u2f: [s: Nat] → [pe: «2; Nat»] → Idx s → math.F (fpe pe);
axm f2i: [pe: «2; Nat»] → [s: Nat] → math.F pe → Idx s;
axm f2u: [pe: «2; Nat»] → [s: Nat] → math.F pe → Idx s;
axm f2f: [spe: «2; Nat»] → [dpe: «2; Nat»] → math.F spe → math.F (fpe dpe);

Phases

legalize

Turns every Nat value and every pointer into an I64, so that isel only sees register types.

axm legalize: compile.Phase;

isel

Instruction selection. -X x86:isel-dot=<file> writes the PBQP graph in Graphviz DOT format, with the chosen options highlighted.

axm isel: compile.Phase;

schedule

Threads every instruction of a block onto the block's mem.M 0 chain. Expects every continuation to take a mem.M 0.

axm schedule: compile.Phase;

spilling

Spills and reloads until at most k general-purpose values are live at every point (Braun & Hack, CC 2009). k is 14 by default and -X x86:k=<n> overrides it.

axm spilling: compile.Phase;

constrain

Moves the operands that an instruction needs in a fixed register, and a two-address operand that stays live, into a fresh continuation right before it. The jump is the copy, so the copies' live ranges end at the instruction and the interference graph stays chordal. The fixed operands are wrapped in in. Likewise, a fixed result that stays live is passed on to a fresh continuation right after its instruction.

axm constrain: compile.Phase;

color

Assigns a register to every general-purpose value by one PBQP per function (Buchwald, Zwinkau, Bersch, CC 2011) and wraps each use of a value in in. Jumps, calls, and returns are parallel copies: their arguments only prefer the registers of the parameters they bind. Removes chain instructions whose results are all dead. -X x86:color-dot=<file> writes the PBQP graph of each function in Graphviz DOT format, with the chosen options highlighted.

axm color: compile.Phase;

emit

Emits GNU assembler code (AT&T syntax) to <world>.s.

axm emit: compile.Phase;

live

Prints the liveness of every scheduled function to stdout, or to -X x86:live=<file>: per block the live-in and live-out values and the maximum number of live values (general-purpose registers, flags).

axm live: compile.Phase;
